# 小红书选品两套系统：需求清单

来源：飞书文章《小红书虚拟电商选品实战：从找商品、盯销量，到发现正在起量的品，我做了两套选品系统》（作者：锦城）及文中 GUI 截图。

标记说明：
- 【文章】文章或截图中明确出现。
- 【推测】由截图或文字反推，需确认。
- 【建议】本项目新增或改进，原文没有。

## 0. 整体流程

```
系统1 找候选(关键词/店铺/整店) -> 本地接口入池 -> 系统2 定时记录销量
 -> 计算增量 -> 超阈值预警(微信/钉钉) -> 人工判断是否跟进
```

原则【文章】：系统只负责盯，不负责替人做决定。

## 2. 系统 2：商品和店铺销量监控

形态【文章】：本地 Web 应用。规模：约 2300+ 单品、140+ 店铺。

### 2.1 监控池
- 添加链接，区分单品和店铺【文章】
- 列表列：图片、名称和 ID、所属店铺、分类、价格、总销量、今日增量、昨日增量、上小时增量、状态、最近抓取时间【文章】
- 工具栏：全选、刷新、抓取所有单品、抓取所有店铺、复制商品链接、复制店铺账号、删除选中【文章】
- 筛选和搜索：只看单品、分类、名称/ID/链接；多列排序【文章】
- 分类管理：新增、改名、删除，删分类不删商品【文章】
- 按商品 ID 去重【建议】

### 2.2 调度【文章】
- 单品：每天 10:00-23:00，每小时一次（每小时的第 N 分钟可配）
- 店铺：每天一次（时间可配，默认 10:00）
- 手动触发全量抓取
- 采集日志页
- 进程重启后补跑漏掉的整点【建议】

### 2.3 快照与增量
- 保存总销量快照；增量 = 相邻两次差值【文章】
- 单品展示今日、昨日、上小时增量，可看每天和每小时变化【文章】
- 店铺只记总销量差值【文章】
- 7 天、30 天增量：作者未做【文章】，建议做【建议】，因为只是对快照的聚合查询
- 快照存原始值和抓取状态，增量在查询时计算【建议】
- 销量只以文本形式返回（如"已售5471"、"已售 3.8万"，接口里没有原始整数），大数值会被平台取整成"1万+"这类区间【用户反馈，格式规则待核实】。处理方式见 2.3.1【建议】

#### 2.3.1 销量取整的处理【建议】

快照表每条记录存：`raw_text`（原文）、`value_low`（解析出的下界）、`step`（该显示格式的精度，精确值为 1，"3.8万"为 1000，"1万+"为 10000）、`is_exact`。

- 增量计算：只有前后两次都是精确值才给出确定增量；否则存成未知，**不记为 0**。
- 跨档事件：前次精确 9987、本次"1万+"，记录"增量 >= 13，且已进入取整区"，并触发一次提醒。
- 取整区的商品：销量变化只在跨档时才可见，所以降低抓取频率（例如每天一次），并按较长窗口（7 天、30 天）看平均速度，不做小时级预警。
- 选品价值：作者关注的是"正在起量"的商品，其价值窗口主要在销量还小、仍是精确值的阶段。进入取整区的商品多半已不是早期机会，监控优先级应下调。
- 替代信号（待核实是否可取）：店铺销量（精度 1000，对头部店铺仍有用）；同一店铺下其他商品的销量；笔记点赞、收藏等互动数。
- 解析规则：`^已售\s*(\d+)$` 为精确值；`^已售\s*(\d+(\.\d+)?)万(\+)?$` 为取整值，下界 = 数值 × 10000，有 `+` 表示"至少"；遇到无法解析的格式，存原文并标记解析失败，不要静默丢弃。
- 实测样本（2026-10-30，无登录会话）：

  | 类型 | 显示 | 说明 |
  |---|---|---|
  | 商品 | `已售5471`、`已售6514`、`已售7832` | 精确整数 |
  | 商品 | `已售1.8万+` | 取整，档位 0.1 万（即 1000），带 `+` |
  | 商品 | `已售12万+` | 取整，没有小数，档位大致 1 万 |
  | 店铺 | `已售 3.3万`、`已售 6.8万`、`已售 14.2万` | 取整，档位 0.1 万，无 `+`，14.2 万 仍带一位小数 |
  | 店铺粉丝 | `粉丝数 15.1万`、`1.2万`、`4.2万` | 与销量无关，仅供参考 |

  从已有样本推测（未完全确认）：商品销量在 1 万以下是精确值，1 万到 10 万显示"x.x万+"，10 万以上显示"N万+"。商品和店铺的取整规则不一样（店铺无 `+`，14.2 万 还带小数），解析时要分开处理。仍缺 8000-9999 这个区间的样本，不确定从哪个数开始取整。

### 2.4 预警【文章】
- 规则一：近 1 小时增量 >= X（作者设 5）
- 规则二：价格 >= Y（作者设 29）且近 1 小时增量 > 1
- 推送渠道：微信（push+）、钉钉机器人
- 消息内容：商品名、店铺、价格、当前总销量、今日新增、近 1 小时新增、触发规则、推送时间
- 规则本质是"销量异动提醒"，不是订单通知
- 连续 N 天增长、加速度、冷却期避免重复推送【建议】

## 3. 作者提到的使用方法（可作为产品需求的来源）

- 按今日增量排序，今天没动的不看；重点看连续性，而不是单日峰值
- 一个商品起量后，扩大样本：同关键词其他商品、同店其他商品、对应笔记
- 选品入口：考试日历、淘宝找需求词、已监控店铺
- 没有系统时，用 Excel 每天记数字做减法也能起步（10-20 个商品，连续 7 天）
